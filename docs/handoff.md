# Forge implementation handoff

Current milestone is one live build on a Forge pull request that posts the rolled-up gate status from a trusted Buildkite lane. [FOR-38](https://linear.app/outfitter/issue/FOR-38) owns that milestone. Its next action is to finish the trusted lane configuration, connect the delivered operations and qualify the run. Until that run exists, new operations without a consumer are on hold.

## What runs today

Forge's GitHub Actions `check` job runs `bun run forge check` and the evaluator CLI fixtures. The [advisory Ropes Markdown job](../README.md#advisory-markdown-check) runs alongside it. Fresh checkouts use `./scripts/bootstrap.sh` with the exact Bun pin in `.bun-version`.

The repository is public under MIT. The package remains unpublished with `private: true`. Consumers can select an immutable source revision, subject to their own runtime and integration qualification. [Standing delivery authority](../AGENTS.md#standing-delivery-authority) and [owned failure recovery](../AGENTS.md#owned-failure-recovery) govern scoped delivery.

## Built and awaiting adoption

[Forge gate](forge-gate.md) collects and evaluates a pull request locally. The root [`forge-gate.json`](../forge-gate.json) declares Forge's policy, but no lane reads it yet. The [Buildkite implementation](buildkite-pipeline.md) includes admission, authenticated host dispatch, project checks, receipt verification and an offline status-refresh preview. Those pieces have offline coverage. The complete trusted lane still needs live qualification. The [Forge pipeline](https://buildkite.com/outfitter/forge), UUID `01a20f28-90bc-45e3-916c-73df140244af`, exists with automatic triggers, webhook processing and automatic status publication disabled. Its stored bootstrap exits with failure until the protected host hook handles an approved job. Recheck those settings before every trial.

Hosted Codex review has [bounded qualification evidence](codex-command-qualification.md) and an [adopted policy entry](hosted-reviewer-attestations.md#adopted-policy-entry). The [local installation and recovery rehearsal](installation-recovery-qualification.md) qualifies a clean source pin, cancellation and receipt retention, and ledger restart behavior. The production lane must still establish authenticated collection, finding completeness and durable ledger custody. Forge's gate needs one acceptable clean review and a complete account of unresolved findings from all reporting reviewers. Ranger owns executing and recovering the review ladder.
