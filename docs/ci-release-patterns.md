# Canonical CI and release patterns

[FOR-22](https://linear.app/outfitter/issue/FOR-22) selects reusable patterns from the audited Trails and Skillset sources for Forge-owned operations. The November 11 direction makes Forge commands primary; a thin public Actions adapter is optional only for a concrete consumer need, superseding the earlier mandatory-adapter architecture. This is extraction guidance, not a deployed workflow or adoption claim. [Design tenets](tenets.md) and the [automation contract](automation-contract.md) govern implementation. Product repositories keep their task graphs, package/artifact contracts, versioning, signing, probe definitions and release policy; Ranger keeps agent behavior.

## Evidence and qualification level

The November 10, 2026 read-only audit inspected Skillset at `24800e02ed4e7150ea1bc7130c35603c98ea9da2`, Trails at `b226d8eddf5ad98245a046a4e8ea9721418ee3a8`, and candidate release-action at `781379183eaf3d4b6139894582e58a47cad28e08`. Links below identify those immutable snapshots, not a claim about later default branches, current environment approvals, credentials or successful live execution. Selected setup/check and policy source was additionally read at these pins for this document. No product tests or live qualification/release mutations were invoked to establish these source observations.

| Evidence | What the source establishes | What it does not establish |
| --- | --- | --- |
| [Trails CI][trails-ci] and [setup composite][trails-setup] | Separate build/lint/type/test/governance jobs, explicit changeset/release-pack applicability, final `CI Gate`; pinned setup actions, Node 22, `.bun-version`, cache identity and frozen install. | That this job list, runtime mix, cache credentials or skip policy fits another product. |
| [Skillset CI][skillset-ci] | A gate must actually run; draft/full tiers, merge-candidate checks, generated-release substitution, stack-aware read-only repair/report behavior. | That its write permissions, detection or source compiler are a safe universal template. |
| [Skillset release][skillset-release] and [policy][skillset-policy]; [Trails release][trails-release] and [policy][trails-policy] | Separate version planning, deterministic intent/policy, approval environments, artifact/registry checks and release reconciliation; revision-aware CI and source checks. | Authenticated producer evidence from a boolean, installed npm grants, qualified Forge source invocation, or permission to publish. |
| [Skillset propagation][skillset-propagation] and [package-set rules][skillset-packages]; [Trails pack coherence][trails-pack] | Bounded immutable-version recovery and product-specific package ordering/coherence checks informed the delivered Forge qualification primitives. | A universal package graph, cryptographic provenance verification, or rollback of immutable npm versions. |

Source behavior is evidence for a pattern, not automatic endorsement of every source implementation detail. In particular, source code includes product-specific assumptions and development overrides; do not carry assumed-CI shortcuts, broad write credentials, mutable references or hard-coded organization identity into trusted shared acceptance.

## Selected patterns and boundaries

“Selected” below means the smallest reusable meaning to preserve. Proposed inputs/results are design boundaries, not exported APIs or a promise that an adapter already exists.

| Pattern | Forge operation or shared configuration | Thin adapter and product boundary | Qualification before adoption |
| --- | --- | --- | --- |
| Setup and frozen dependencies | Reuse configuration first: explicit consumer runtime pins, working directory, lockfile identity and OS/architecture cache partition. Cache reuse accelerates installation; it never supplies a passing check. | Product declares required runtimes and install command. Adapter installs the declared versions and performs frozen install. Trails' Node 22 setup and Node 24 publishing runtime serve different roles; Forge retains its exact Bun 1.4.4 pin. No default organization cache credentials or Node requirement is inferred. | Wrong/missing runtime or lockfile fails; a cold cache works; each checkout owns dependencies. Existing [Forge bootstrap](../scripts/bootstrap.sh) already qualifies this repository's setup. A public setup surface needs a concrete consumer before extraction. |
| Changeset guard | Normalize exact repository/head/base, changed paths/statuses and explicit product applicability/exemption policy; report required/satisfied/exempt/blocked with reasons. Reuse the product guard until its semantics are actually shared. | Adapter collects complete revision-bound changes, not a guessed Git diff against moving main. Product owns release-relevant paths, package mapping, generated version-PR handling and any audited label exception. | Missing/truncated change data, wrong base/head, renames/deletions and unsupported exemptions fail closed. [Trails][trails-ci] passes a base ref and release-none intent; [Skillset][skillset-ci] uses name-status diff and treats generated release heads separately. Those exceptions are not interchangeable defaults. |
| Final gate summary | Keep an explicit required job/result map and event-specific expected skips. Prefer the small repo-owned final job to a new runner; extract pure aggregation only when a concrete consumer needs it. | Product owns task dependencies and job IDs. Adapter collects producer/run/revision-bound results and renders the same decision. PR checks and merge-candidate integration checks retain their different subjects. | Failed, canceled, missing, unknown or unexpectedly skipped jobs block. An intentional event exemption is explicit and reported. Trails' `always()` summary expects PR-only jobs to be skipped on other events; it does not accept every skipped job. Existing [evidence evaluator](evidence-evaluator.md) remains the owner of its six gate semantics. |
| Deterministic release policy | Select a pure policy-evaluation extraction under [FOR-19](https://linear.app/outfitter/issue/FOR-19): explicit repository/ref/subject, product policy, intent families, release diff/version facts, CI proof and artifact/registry decisions in; auto/manual/none/block eligibility with reasons out. Separate safety blockers from conditions that only exclude automation. | Product chooses labels/channels, trusted actors, allowed version-only changes, stack-boundary policy, package version model and approval rules. Adapter authenticates collection, preserves proof provenance and maps an eligible result to existing protected environments. A decision grants no publishing authority. | Conflicting/unknown intent, stale or incomplete required proof and unsafe artifacts cannot be waived by model output or an approval click. Preserve tested source behavior where shared; make each deliberate policy divergence explicit. Do not copy a product's repository name, stable-only rule or assumed CI flag as a shared default. |
| Artifact and registry evidence | Reuse delivered [FOR-24 artifact validation](package-artifact-validation.md) and [FOR-18 immutable npm evidence](npm-evidence.md); do not implement competing checks in YAML or another publisher. | Product supplies expected artifact identity/contract and package set; trusted collectors bind actual packed bytes and clean-consumer results, then collect registry evidence. Product keeps native target/dependency order and signing policy. | FOR-24 is offline qualification of finite dependency-free libraries and normalized evidence; FOR-18 checks registry metadata and predicate references. Neither authenticates a producer, supplies a production collector, proves tarball bytes from registry metadata, or authorizes a republish. Conflicting occupied integrity blocks; incomplete visibility stays bounded and recoverable. |
| Generated-output repair and reporting | Share the read-only assessment/report boundary first: exact subject, allowed generated paths, deterministic command outcome and proposed diff. Preserve the distinction between problems remaining and a gate never running. | Product owns its compiler/fixer. A separately authorized trusted writer rechecks exact head, validates permitted paths and produces a new commit; proposed code must not receive privileged write credentials. Forks, merge groups and parents with active child branches remain read-only unless separately authorized. | Exercise no-op, remaining errors, absent gate, wrong head, forbidden edits and stale repair attempts. A summary or comment is not fresh CI on a repaired head. Skillset notes that its `GITHUB_TOKEN` repair push does not retrigger workflows; do not solve this by silently adding a PAT. |

## Release extraction inputs for FOR-19

Select policy evaluation next, composed with the existing artifact/registry operations. Do not move an entire release workflow or invent a publisher framework. [Candidate release-action policy][candidate-policy] is source material alongside the newer product implementations; its [registry check][candidate-registry] and [short publish polling][candidate-publish] are superseded as extraction references by FOR-18's focused qualification, not retired in their existing repository.

Preserve three revision identities when they differ: the workflow/trusted orchestration revision, the prepared release source revision, and the artifact digest. Trails' publisher checks out the workflow's `github.sha` and compares selected package trees against the separately prepared release SHA. Skillset's native/publish jobs instead select the planned version commit and its named artifacts. These are explicit product mechanisms, not evidence that any two SHAs are equivalent. [TRL-1425](https://linear.app/outfitter/issue/TRL-1425) tracks the Trails provenance question; this extraction does not close it.

CI proof also differs. Skillset's inspected collector requires its `check` and `skillset-ci` results from GitHub Actions at the exact SHA. Trails models proof sources, including exact SHA and a release-PR-head proof selected using tree/commit facts. Its labels/channels and stack evidence differ too. A shared operation must retain the proof source, tested subject, required checks and any explicitly authorized equivalence conditions; never reduce both to an unbound `ciPassed: true`, or silently admit an “assumed” proof source. Producer authentication and complete collection remain collector responsibilities.

A separately released implementation should adapt existing pure policy branches and offline fixtures, then add cases for conflicting intent, missing/stale CI, unsupported proof equivalence, wrong repository/ref/actor, unsafe version diffs, wrong artifact integrity and incomplete package sets. Manual approval may authorize an otherwise permitted action; it cannot erase evidence that consumer policy requires. Auto/manual environment names in a workflow do not prove installed reviewer protections or credential scope. Actual publish/tag/release mutation and live qualification remain separate authority.

[FOR-20](https://linear.app/outfitter/issue/FOR-20) preserves existing Actions consumers and aligns their documentation; it is not a blanket prerequisite for the Forge CLI. Matt selected public Forge source reuse; [FOR-25 preparation](public-readiness.md) precedes a separately authorized visibility change. Once public, the source-fetch path no longer needs a cross-owner private-repository credential. A future public adapter still must declare and qualify its immutable Forge/adapter revisions, runtime and invocation contract. [Private distribution analysis](private-distribution-analysis.md) is superseded; [selected-consumer results](distribution-qualification.md) remain dated same-owner evidence. [FOR-23](https://linear.app/outfitter/issue/FOR-23) owns later monorepo adoption. No adapter reference is qualified by this document.

## Evidence for the Belay decision

[FOR-21](https://linear.app/outfitter/issue/FOR-21) now maps useful Belay/Actions capabilities to subsume into Forge, with a keep/narrow/retire recommendation for actual consumers. Do not restore Belay as a product or remove current users’ paths as part of extraction. The audited [Belay workflow][belay] infers commands/risk tiers through its detector and provides broad CI orchestration. Trails and Skillset demonstrate explicit repo-owned commands, event-specific checks and separate setup/reporting pieces instead. This supports explicit product task graphs as the default extraction boundary; it does not establish that Belay has no users or that it should be deleted.

The useful pieces to evaluate independently are setup/cache configuration, normalized changed-file facts, explicit final-result aggregation and read-only reports. Do not promote detector guesses or a generic risk tier into authority to omit required product checks. Before changing Belay's disposition, FOR-21 should establish real consumers and their requirements, compare these small pieces against the workflow's current benefit, and qualify a replacement for any affected consumer. No workflow removal, redirect, tag change or consumer migration is selected here; the audit's scoped caller search is not proof of zero consumers.

Keep domain behavior local: Trails Warden rules/configuration and its [published-package check adapter][trails-check], Trails governance/contract/adapter checks, Skillset source compilation/generated formats, native platform matrix/signing/notarization, product release ordering, changelog/version policy and Homebrew handoff. A command wrapper can be thin without making the command's product meaning a Forge responsibility. Homebrew draft PR creation, tap publication and product release publication remain distinct authorities; this document does not combine them into a shared release action.

## Delivery and next qualification

This documentation slice fulfills the pattern classification and candidate selection in FOR-22. It does not implement the selected policy/guard/summary/repair operations, settle Belay, restore Actions health, adopt an adapter or requalify a live release. FOR-18 and FOR-24 remain the implemented reusable release-evidence primitives. FOR-19 consumes this map for a separately scoped extraction; FOR-21 consumes the comparison for its owner decision. Run the owning Forge checks for documentation changes, then require independent review. Live consumer, provider, publisher, signing, access and worker decisions retain their existing boundaries.
