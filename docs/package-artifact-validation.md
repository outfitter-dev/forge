# Pre-publication package artifact validation

[FOR-24](https://linear.app/outfitter/issue/FOR-24) adds `evaluatePackageArtifact(contract, subject, packedEvidence, consumerEvidence)` to the existing Forge package. It evaluates evidence from an actual packed artifact and a disposable consumer. This is separate from [FOR-18's post-publication registry observation](npm-evidence.md); neither operation publishes anything. Product owners retain versioning, build graphs, signing, packaging format, probe implementations and release policy. [MONO-83](https://linear.app/outfitter/issue/MONO-83) owns the frontend monorepo's source-versus-built choice; Forge does not settle it.

## Contract and supported slice

The product explicitly declares package name/version, an exact file allowlist and required subset (including `package.json`), exports/entrypoint values, runtime identity, and named install/runtime/type checks. All three check kinds are required. Optional allowlisted files may be absent; every file outside the allowlist blocks. `packageArtifactContractDigest(contract)` hashes the exact serialized contract with SHA-256 and returns `null` for invalid/unsupported input. Preserve the contract as serialized: exports key order affects condition priority. Reordering conditions changes both expected behavior and the digest; do not sort them mechanically.

This first slice covers dependency-free library artifacts with explicit finite exports: string, blocked `null`, named subpaths and nested conditions. Export paths must stay inside the package, and every non-null declared target must be packed. `main`, `module`, `types` and `typings` are checked when declared and must also be absent when the contract omits them. The actual exports tree must match the contract, including condition order. Paths are bounded relative POSIX file names without empty/dot/parent/`node_modules` segments, whitespace, backslashes, colons, percent encodings or wildcards. Exports traversal is bounded to 1000 nodes, ten nested levels and 100 keys per map; lists are bounded to 1000 files and 100 checks.

Exports patterns/fallback arrays, mixed subpath/condition maps, dependency/optional/peer sets, package `imports` and executable `bin` maps remain unsupported. They cannot receive a false pass. Invalid contracts return `invalid` with no binding; unsupported actual package shapes return `unsupported`. Extend support only with a concrete consumer and offline resolution/installation proof; this module does not infer an install graph or rewrite product manifests. Both built JavaScript/declarations and source TypeScript are demonstrated under the explicit Bun fixture contract, without prescribing either layout to products.

## Evidence and binding

The subject supplies repository (`owner/repo`), immutable 40-hex source and validator revisions, and the canonical staged tarball SHA-512 SRI. Trusted packed evidence supplies the digest, regular-file list relative to the package root and manifest read **from that same tarball**. The evaluator never consults source files. It rejects duplicate/unsafe/sparse file lists, inconsistent manifest identities, missing files/targets and undeclared entrypoints. A source workspace's successful build cannot supply a missing packed declaration or implementation.

Consumer evidence must match the exact repository, source revision, validator revision, artifact integrity, contract digest and runtime identity. It must account for exactly the declared check IDs with no duplicates; every check must pass. Failed, canceled, incomplete, unsupported, missing or stale results block completion. The collector must establish a disposable artifact-only installation and successful cleanup. Returned decisions retain only known binding fields and reason codes/paths/check IDs; raw manifests, arbitrary fields, process output and errors are omitted.

**Shape and matching do not authenticate collection.** These inputs are trusted normalized observations, not self-authenticating product assertions. The pure operation has no filesystem, archive parser, subprocess, provider or credential access. It cannot prove an arbitrary supplied file list came from its claimed digest, that a process actually ran, or that a claimed consumer was isolated. The trusted collector must establish those facts before normalization and bind the validator/check implementation and product probe definitions to the stated revisions. Do not manufacture current bindings around old or unbound results.

The collector owns bounded archive inspection, rejecting duplicate entries, symlinks/hardlinks, traversal, ambiguous names and unsupported entry kinds before normalization; hashing the exact immutable packed bytes; manifest/file collection from those bytes; and installation of those same bytes in an external disposable consumer. It must prevent workspace links, inherited path mappings/configs and hidden workspace dependencies from supplying files, run every declared probe, enforce resource/time/output limits, release processes and remove its disposable paths. Cleanup failure must remain a blocker. Retain sanitized failure evidence before deletion, outside credentials/state. Artifact content and probe code are executable proposal code: use an appropriately isolated, unprivileged, credential-free host. A local temporary directory or normalized isolation label is not an OS sandbox or network enforcement boundary.

## Offline qualification

`tests/package-artifact-consumer.ts` is a fixture-only collector for synthetic regular-file packages created by this suite. It is deliberately not exported as an untrusted archive extractor or general product runner. It packs with pinned Bun using `--ignore-scripts`, hashes the tarball and reads its actual manifest/files with `Bun.Archive`, then installs that local tarball with `--offline --ignore-scripts --backend copyfile` and a fresh cache. Source and consumer directories are separate under a new temporary root outside this repository; the installed package is checked against a workspace symlink. The consumer uses its own config and type-check project, no inherited environment beyond executable search/color, and `--no-env-file`. Each subprocess has a five-second timeout and the temporary root is removed in `finally`, including negative cases. This proves behavior for the controlled fixtures; it does not qualify hostile archive parsing or production isolation.

Real artifact tests cover a built package, a source TypeScript package, source-only hidden runtime code (workspace passes, packed consumer fails), incompatible published declarations (runtime passes, types fail), a declaration excluded from the pack, and an unexpected packed file. Deterministic tests cover missing/unsafe/duplicate files, exact manifest/export/condition checks, unsupported shapes, every stale binding, missing/extra/duplicate or failed/canceled/incomplete/unsupported consumer checks, isolation/cleanup failures, contract changes and receipt sanitization.

Run `bun install --frozen-lockfile` and `bun run check`. All fixtures are local and credential-free; there is no registry publication, product migration, public adapter, credential expansion or worker operation. An adopted collector, additional dependency graph/runtime support and live product qualification remain separate work with explicit authority.
