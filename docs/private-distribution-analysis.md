# Private distribution analysis

[FOR-6](https://linear.app/outfitter/issue/FOR-6) requires a route grounded in actual consumer/access decisions, including authorized success and denied access for intended private/public uses. This November 10, 2026 analysis recommends a first route and proposes disposable qualification. It does not establish consumer access or complete the live criteria. No consumer, package, grant, credential, workflow permission, worker, or production integration was created or changed.

## Verified starting point

Forge (`outfitter-dev/forge`) is private. Read-only GitHub metadata reports Actions sharing `access_level: none`. That is the current setting, not a recommendation to change it. Repository source at `44a6777aa213ee8cb29847db900221a726dcbaaf` has a self-CI workflow, no `workflow_call` consumer interface, no published distribution, and `package.json` marked private. The pure evaluator and local Bun CLI are usable source operations; no consumer build graph or provider framework is needed to share them. The existing CLI's runtime imports need no production package dependency; repository development checks use frozen pinned development dependencies.

The current workstation identity can read Forge. This does not prove that a `galligan` repository's CI token, a public/fork job, a package consumer, or another runner can read it. Existing Studio/Rex infrastructure is established (see the handoff; its dated read-only refresh is in [PR #11](https://github.com/outfitter-dev/forge/pull/11)). Do not ask Matt to choose a host again. A different consumer's access and permitted execution remain separate decisions; no worker deployment is needed for analysis.

## Route comparison

| Route | What it supplies | Access/integrity/runtime obligations | Decision |
| --- | --- | --- | --- |
| Immutable authenticated source checkout and shared-code invocation | Existing evaluator/CLI, with a thin trusted caller; no new package or service. | Explicit Forge identity, full trusted commit, approved repository-read credential, protected fetch outside proposal cleanup, verified commit/tree, Bun 1.4.4, and a separate product task graph. | Recommended first route for a selected private consumer or trusted external host. Access still needs qualification. |
| Private immutable artifact | A small prebuilt/source bundle can avoid a full checkout. The pilot's private ZIP proves packaging, not universal distribution. | Select store/asset identity, read permission, retention, trusted source-to-digest receipt, expected digest from an independent trusted channel, extraction safety, runtime/dependency manifest, and rotation/revocation. | Defer until a consumer actually needs an artifact. No artifact store or publication pipeline is justified yet. |
| Private package | Familiar version/lockfile installation for package consumers. | Publishing approval, supported registry/runtime/export contract, package ownership/ACL, exact version plus integrity, authenticated install and denied-access tests, expiry/rotation. Registry permissions differ from repository access. | Defer: Forge has no published consumer package and this adds a release/access surface before a demonstrated need. |
| Private reusable workflow/action | Service-native reuse can fit supported same-owner private callers once a concrete interface exists. | Called-repository Access policy, caller Actions policy/visibility, immutable pin and service-native resolution; does not elevate caller credentials. | Not the first operation's existing interface, not enabled today, and not a general cross-owner/public solution. |

GitHub documents [private organization sharing](https://docs.github.com/en/actions/how-tos/reuse-automations/share-with-your-organization), [same-user private sharing](https://docs.github.com/en/actions/how-tos/reuse-automations/share-across-private-repositories), and [enterprise sharing](https://docs.github.com/en/actions/how-tos/reuse-automations/share-with-your-enterprise). Organization sharing does not grant a personal `galligan` caller access; enterprise rules require actual membership/visibility/policy and must not be assumed to cover that personal account. Native private sharing can indirectly expose code/logs to outside collaborators on consuming repositories, so the owner must approve that transfer.

The official [workflow access reference](https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations#access-to-reusable-workflows) allows a public caller to use public reusable workflows, not private ones. Reusable workflows are resolved at job-level `uses`; a checkout step cannot run inside that calling job to repair unavailable workflow resolution. Authenticated checkout enables ordinary shared-code invocation in steps; it does not make a private `uses: owner/repo/.github/workflows/file.yml@sha` resolvable.

[GitHub Packages authentication](https://docs.github.com/en/packages/learn-github-packages/about-permissions-for-github-packages) is a separate model. Private cross-repository installs need package read access; a caller `GITHUB_TOKEN` works only with the relevant package permission. The documented PAT alternative is a classic token with at least `read:packages`, not an invented interchangeable fine-grained repository token. A registry migration or broad classic token is not necessary for the current source operation. No package is published by this recommendation.

## Recommended first invocation boundary

Select a trusted Forge commit outside the proposed product checkout and freeze it in the consumer's approved configuration. Authenticate only to the explicit source repository. Fetch/resolve the full commit and verify the resulting object against that configured pin, not a branch/tag or SHA supplied by a proposal. A matching hash establishes content identity, not independent publisher authentication: source origin, selected credential, approved pin, and protected transport/configuration remain part of trust.

Use a currently approved repository-scoped read credential where one actually exists. A short-lived GitHub App installation token limited to Forge contents read is preferable when already available; an explicitly approved repository-scoped read identity is another possibility. Do not provision an App, mint a PAT, grant a personal repository organization access, or broaden an existing token incidentally. Matt must select custodian, effective permissions/SSO requirements, protected delivery and expiry/rotation for the actual consumer. Record no values. A Devin API token supplies no GitHub distribution authority.

Keep fetch credentials out of remote URLs, logs, persistent Git credential helpers, archived `.git`, artifacts, and proposed task environments. Remove transient delivery and helpers after fetch even on failure. Do not expose the fetch secret through later proposal code, inherited environment, home mounts, or a broadly writable shared workspace. An Actions implementation must explicitly avoid persisting checkout credentials and must use a trusted job/revision; merely omitting the token from a later shell environment is insufficient isolation. Untrusted PR/fork code must never run beside this credential or private Forge checkout.

Invoke the trusted CLI with explicit facts and policy paths, or import the same evaluator from the trusted source. Pin Bun 1.4.4 and supply only required runtime files; if running development checks, use frozen locked dependencies in a separate trusted environment. Keep task graphs in the product repo and collection/authority outside proposed code. Compare actual output and exit codes with the same operation's fixture contract. Source transfer grants neither status publication nor merge/release authority.

For public consumers, private source in a public workflow is an exposure decision, even if authentication works. Recommend first proving a trusted external-host invocation using public harmless facts and publishing no private source/logs/artifacts; the public/fork job receives no Forge credential. The established Studio can host a bounded trusted invocation when explicitly released. This demonstrates that specific external-host mode only, not public GitHub-hosted workflow reuse or package access. Any public reporting write, private-code transfer to a public runner, or broader adoption needs its own approved boundary.

## Proposed disposable consumers and qualification

Propose the existing private `outfitter-dev/agentic-ci-pilot` for a same-owner control, a private `galligan/forge-distribution-pilot` for cross-owner shared-code invocation, and a separate public `galligan/forge-distribution-public-pilot` for the external-host/no-secret-public-job boundary. The latter names are proposals, not verified availability or creation authority. Matt must select actual identities, collaborators/readers and whether the public mode meets his intended need before any live test. Do not migrate a production repo or change Forge visibility.

The eventual packet must identify source and consumer IDs/visibility, exact source/policy/Bun pins, caller/credential identity, minimum effective read permissions, protected delivery, retention/readers, time/request budget and cleanup owner. Freeze it before execution. Prefer one passing and one denied attempt per selected route, one intentionally wrong pin/integrity case, and no provider calls or product build migration.

| Case | Required evidence |
| --- | --- |
| Authorized private control/cross-owner | Actual selected consumer execution fetches the approved immutable Forge source under the selected read identity, verifies integrity, and invokes the same CLI fixtures with expected 0/1/2 outcomes. Workstation access alone is not this result. |
| Denied source access | Missing or deliberately non-authorized test identity cannot fetch private Forge; consumer exits blocked before invocation, without fallback to public/mutable/ambient credentials. Do not revoke a shared real credential merely to stage this case. |
| Wrong source/integrity | A wrong commit, changed artifact, or incompatible runtime fails before any eligibility claim; a digest fetched from the same untrusted substitute is not an independent expected digest. |
| Public boundary | The chosen trusted external-host mode can read allowed public fixtures and invoke private Forge without transferring private source/credentials/logs to the public/fork job. A no-credential public job remains denied. Report only permitted minimal fixture decisions, if reporting is separately authorized. |
| Expiry/rotation and cleanup | Record configured expiry/custodian/renewal and a bounded simulated unavailable/expired-credential failure. Any real rotation requires its own authority. Remove only selected temporary fetch material/consumer fixtures, preserve private receipts for the approved retention period, and confirm no persistent helper or secret-bearing artifact. |

Record authenticated fetch/service references without headers or values, expected/actual denial, exact source/digest/runtime, caller identity/visibility, CLI receipts and boundaries. Read-only documentation and offline fixtures do not qualify cross-owner CI access. Do not claim public support from a private-only success or fixture compatibility from a package that was never published.

FOR-6 remains open until actual consumer/access decisions and authorized success/denied-access evidence satisfy its acceptance criteria. The concrete near-term choice is immutable authenticated source invocation; artifact/package/native-workflow routes remain conditional alternatives. No new distribution helper or abstraction is implemented before a selected consumer establishes the required transport.
